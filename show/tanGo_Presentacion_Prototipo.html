03 · El algoritmo

Tres pasos por tick.
1 tick = 30 segundos simulados

PASO 01
Presión propia
Cada intersección suma los pesos de sus entidades (vehículos, peatones, emergencias) y calcula su presión de tráfico local.
→
PASO 02
Mente colmena
Los semáforos vecinos se comunican. Si un nodo lleva suficiente tiempo en verde, genera una ola que prepara a los de aguas abajo.
→
PASO 03
Ajuste de fases
El nodo con mayor presión en su cluster gana el verde. Los demás ceden. Si no hay entidades: modo BLINK para ahorrar energía.
# Fórmula de presión propia
presión = (Σ pesos_entidades / peso_vía × node_weight × multiplier) × 100

Contexto · lluvia
Peso del peatón ×1.3. El sistema sabe que llueve y da más tiempo para cruzar.
Horario nocturno
00:00–05:00 → vehículos ×1.5, peatones ×0.8. La ciudad cambia de lógica.
Override de emergencia
Peso 999 → todas las fases a rojo instantáneo. Sin excepción, sin demora.

07 · Stack tecnológico

Construido sobre
tecnología probada.

Core del algoritmo
Python NetworkX Dijkstra
Grafo vial real descargado via Overpass/OSM. Hasta 1,500 nodos con radio de 3km sobre la ZMG.
Base de datos & orquestación
Neo4j Airflow FastAPI
Grafo de la ciudad en Neo4j. Airflow orquesta los pipelines. FastAPI expone la API en tiempo real.
Visualización & datos externos
Leaflet.js Plotly TomTom API Open-Meteo
Mapa interactivo en vivo. Datos de tráfico y clima en tiempo real para ajuste de pesos contextuales.
core/
  algorithm.py   ← TrafficAlgorithm — SCOOT + mente colmena
  entities.py    ← Vehicle, Pedestrian — velocidades por tipo de vía
  weight_engine.py ← WeightEngine — presión ponderada + green wave offset
graph/
  city_loader.py  ← OSM via Overpass, compute_static_weights (5 dimensiones)
  city_graph.json  ← Grafo real ZMG hasta 1500 nodos
